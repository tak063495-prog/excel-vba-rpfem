## 2. 結果をどう解釈するか

- 上下界は**設定した領域・拘束・材料・荷重・解析政策**に対する値です。GAPが狭くても、解析領域が小さい、拘束が過大、荷重を間違えた場合のモデル誤差は除けません。
- `OPTIMAL`は個々の円錐求解にも現れます。全解析の`outcome`、`run_end`、監査、根探索、GAPを合わせて確認します。
- `PARTIAL_CERTIFIED`は、監査済み端点があっても目標区間幅やFs探索条件が未達の状態を含みます。完走したという理由だけで目標精度達成にしません。
- `CERTIFIED`や監査PASSは有限精度での数値検査です。真の実数での厳密区間証明、地盤調査の不確実性、設計基準への適合をまとめて認証する表示ではありません。
- 下界と上界の単純な平均を、コードが認証した唯一のFsとして使いません。必要なら区間と解析政策を併記します。
- 異なる実行の下界と上界をログの数値だけで合成しません。保存場、入力、領域、荷重、Davis政策、監査の同一性確認が必要です。

実問題に使用する前に、既知解との比較、領域寸法・境界距離・メッシュ・積分条件の感度を確認してください。本版ではこれらの全条件を一括検証していません。

## 3. 強度と流れ則

材料データE列のψの空欄はφとして読み込みます。非関連のψ=0を意図する場合は0を明記します。ASSOCIATED政策では低減後のψ=φとして計算します。

DAVIS_EQUIVALENTの結果はDavis等価関連モデルに対する上下界です。元の非関連問題を直接解いた結果と同じ意味にはしません。Fsでの定義は「c/F、atan(tanφ/F)→固定入力ψのクリップ→Davis変換」で、ψもFで低減する定義などとは異なります。[変換式](PRINCIPLES_JA.md#5-fs探索とdavis等価関連モデル)

c=0を小さい正のcへ置き換えたり、求解が止まるためにcを増やしたりすると、円錐の性質だけでなく物理モデルも変わります。ロバスト化の代用として、その結果を元条件のFsとして使いません。小さい正のcでも数値的な難しさが残る場合があります。

φ=0の専用分岐とc=0に対するHSD経路は別です。「φ=0だから常に同じHSD経路」とは判断しません。

## 4. 多層と剛体界面

層ごとに領域・材料IDを設定できます。ただし、次の実装上の前提を確認してください。

|対象|扱い・確認|
|---|---|
|異なる土材料の内部辺|上界では速度連続のbond。独立した摩擦すべり面ではない|
|土と剛体の内部界面|剛体運動と結び付ける。任意の剥離・摩擦接触モデルとして使わない|
|境界面の「剛体」拘束|指定剛体の速度へ結び付ける|
|同一剛体内の辺|剛体運動の内部辺で、土の散逸辺と同じには数えない|
|剛体固定・回転中心|X/Y/回転の固定、中心、外力・モーメントを確認|

材料境界に別の接触c・φを入力する表はありません。弱層そのものを土領域で表すモデルと、界面接触モデルを区別します。薄い弱層がメッシュに表現されているか、領域境界と材料割当てを図で確認します。

G1R11の新しい下界試行制御と赤緑追加経路は、剛体ありモデルを対象外にします。剛体ありの通常SRMを禁止する意味ではありませんが、今回のG1R11全剛体回帰は未実施です。パイロット・Schur剛体設定を同時に有効化して、土のみの検証を剛体の検証として使いません。

## 6. 図・応力・計算時間

赤い矢印は表示長さを規準化した上界速度機構です。大きさをmmの変位、沈下、物理的なm/sへ換算しません。出力速度の規準化は参照仕事によるもので、ケースをまたいでそのまま振幅比較する値でもありません。

下界のSxx・Syy・Txyは引張正のBernstein係数です。頂点・辺中点の節点値と混同せず、必要なら基底で場を評価します。上界と下界が別メッシュの場合は、対応する座標・結合と合わせて扱います。

G1R11の速度改善は、メッシュ経路と追加規模、下界の試行位置を改善する狙いです。要素・積分次数・線形解法の費用次第で計算時間は増え得ます。全解析の短縮率は未測定です。

HSD_SOLVE_SECONDSは**1回の求解**の時間予算で、全Fs探索・全適応解析の制限ではありません。反復の境界で確認するので、長い因子分解中に秒数ぴったりで中断するタイマーではありません。予算を過ぎた点は未判定で、崩壊・安定の証拠にしません。

画面B11はTimerから24時間で剰余を取る実装です。24時間以上の比較はログのelapsed_s、`run_start`と`run_end`で評価します。メモリの値にはExcelプロセス全体やプロセス寿命のピークが含まれるため、開いている他ブックの影響も考慮します。

GAPとFS_TOLは別です。精度を満たしたように見せるためにGAP、監査条件、根幅を緩める変更は行いません。速度の比較は同じ物理条件と精度条件で行い、変更したメッシュ予算・求解数も記録します。

## 7. 解析中の入力とマクロ

解析中の材料・形状・荷重・拘束・設定の変更は、INPUT_MISMATCHとして停止する設計です。EnableEvents=Falseでもsnapshot検査を使います。ユーザーが変更した入力を黙って旧値へ戻す処理ではありません。

- 実行中は入力を変えず、別ケースの解析を重ねて開始しません。
- 中止は「中止」ボタンを使い、次の確認点まで待ちます。強制終了すると最終出力・後片付け前に止まり得るため、その表示を採用結果にしません。
- `RPX_Setup`はシートと図形を消して標準入力を作る初期化です。配布モデルの通常実行や入力保持を期待する操作に使いません。
- TEST_INJECTIONは0です。試験用Probe・代替Evaluate・代替監査を運用ブックへ入れません。
- 通常のマクロ実行と、自動VBAプロジェクト編集のアクセス許可を区別します。全マクロの一括許可やレジストリ変更を通常手順にしません。
- `.xlsx`で保存したり、マクロを保持できない表計算ソフトやライターで再保存したりしません。

## 8. 停止した場合の確認

|表示・ログ|意味|まず確認すること|
|---|---|---|
|INPUT_MISMATCH|実行中の入力がsnapshotと違う|変更セル・式の再計算・外部リンクを確認し、入力を確定して新しい実行を開始|
|MATERIAL_RANGE / DILATION_RANGE|材料値の範囲外|c≥0、0≤φ<89、0≤ψ≤φ、γ≥0、単位を確認|
|未定義ID・面経路エラー|材料/領域/点/剛体の参照、境界順が不正|入力表と図、循環フラグを確認|
|ZERO_REFERENCE_LOAD|上界の規準化に使う参照仕事がない|比例荷重、自重、拘束とFsの荷重変換条件を確認|
|HSD_SOLVE_BUDGET_EXCEEDED / NUMERICAL_UNKNOWN|時間予算等で数値判定できない|どのF・上下界・要素数で止まったか確認。物理的な不安定へ読み替えない|
|HSD_NOT_CONVERGED / CONIC_STEP_STALLED等|数値求解が条件を満たさない|原式残差、backend、求解条件、同じモデルでのPython保存場監査を比較|
|PHYSICAL_AUDIT_FAILED / AUDIT_FAILED|元の物理条件を満たさない|場・荷重・積分・単位・モデル同一性を確認。監査を無効にして採用しない|
|HSD_STABLE_UNAVAILABLE_MEMORY / エラー7 / CAPACITY_EXCEEDED|解法や配列の容量・メモリ不足|停止結果を保存し、要素数・作業上限・Excelのビット数とメモリを確認|
|エラー9・未知例外|配列範囲や実装・入力の異常|通常の再メッシュ失敗として無視せず、発生工程と再現入力を保存|
|fs_upper_limit_fallback / adapt_staged_rejected|既知の失敗や不採用から従来探索/保存場へ復帰|このイベントだけで全解析失敗とは限らない。最後の監査とoutcomeを確認|
|PARTIAL_CERTIFIED|端点は保持したが全目標未達などが残る|GAP、Fs根幅、RFsSearchNote、最終ログを確認|

`INFEASIBLE`や`UNBOUNDED`は円錐問題の分類です。Fs内部には、監査した証拠を使って符号判定する専用の枝があります。単にこの単語だけを拾って実地盤の破壊と同じ意味にしません。上界/下界、試行F、証拠・外側監査と合わせて読みます。

再現を調べる場合は、次を同じ実行の組として保存します。

1. 使用版・コミットまたは配布ハッシュ、Excelのビット数。
2. 計算に使ったXLSMコピーと、材料・領域・面荷重・剛体・設定。
3. RPFEM_logsの該当analysis.tsv全文。
4. 最後のsolve_id、上下界、試行F、要素数、error_originとrun_endの有無。
5. 比較するPython実行のモデル・メッシュ・積分次数・解析政策・目的値・保存場監査。

同じFsでPythonが値を返したという情報だけでは照合になりません。メッシュ、φ/ψの変換、荷重、自重、剛体条件、積分、規準化が同じか確認します。

## 9. 従来経路へ戻す

配布版の設定B48とB50をともにLEGACYへ変更すると、追加赤緑細分化と新しい下界試行制御を止めます。メッシュの土台は従来経路になります。G1R10の直接細分化設定への完全な復元とは区別します。

G1R12のIssue修正を戻す場合はG1R11原本の別コピー、または`versions/G1R12/rollback_cp932/`の`RPX_Control`・`RPX_Output`・`RPX_Robust`を使います。[G1R12からG1R11への復元](../versions/G1R12/IMPORT_ROLLBACK.md)

さらにG1R10まで戻す場合は前版の保全原本、または`versions/G1R11/rollback_cp932/`の別の3モジュールを使い、B48=ROBUST_REFINE、追加した設定の整理、コンパイルを行います。G1R12のrollbackとは対象が異なります。[G1R11からG1R10への復元](../versions/G1R11/IMPORT_ROLLBACK.md)

今回の2026年10月9日のGitHub更新は説明資料の追加です。配布XLSM・ZIP、VBAソース、過去の試験証拠・SHA-256は変更していません。
