# rc9c operator test plan (not executed)

No Excel/VBA, Python reproduction, compilation, build, or numerical test was run while preparing these deliverables. The tests below require a later operator run in an approved Windows Excel environment. Static source checks do not establish numerical acceptance.

## Preparation

1. Keep the original workbook and `rpfem_native_x64.dll` unchanged. In a separate working copy, manually replace the corresponding VBA standard modules with `vba_rc9c/*.bas`, including the new ASCII `RPX_Clock.bas`. Retain the unchanged workbook class code. Check the project with VBA's **Debug > Compile** when performing the later operator validation. The reproduction driver never accesses `VBProject`, imports modules, builds a workbook/DLL, or alters Excel macro-security settings.
2. Place the unchanged DLL beside that operator-prepared rc9c `.xlsm`. Record workbook/DLL provenance and module-import details. Install the driver dependencies `psutil` and `pywin32` through the normal environment provisioning process. Close all Excel processes and avoid opening another Excel instance during testing.
3. Run the supplied standalone driver from this folder, selecting a new output subdirectory. Example for the later operator session:

   ```powershell
   powershell -NoProfile -Command "python .\repro_rc9c.py --workbook .\operator_rc9c.xlsm --out .\repro_results_rc9c --scenario all --wall-limit 2400"
   ```

The driver imports no COM libraries and opens no Excel instance when imported or when displaying `--help`. It starts one isolated Excel process per scenario and operates only on private workbook/DLL copies under `--out`. The combined deadline includes startup, mesh generation, macro execution, and cleanup, with a 30-second cleanup reserve per scenario. Cleanup verifies PID and process creation time and never kills Excel by image name. Source workbook/DLL SHA-256 hashes and the copied DLL hash must remain unchanged. A source-hash mismatch or owned Excel requiring forced termination fails the run.

## Controlled comparison

Both scenarios embed the same P02A_THIN geometry/material/boundary input as the rc9b reproduction and use the same product preset, numerical tolerances, solver gates, and short overrides. Important common controls are `TARGET=320`, `CYCLES=1`, one thin upper round with cap 800, no lower/extra rounds, `GAP=0.000001`, `FS_TOL=0.0001`, and `ACCURACY_DLL_UPPER_EQUILIBRATE=1`. Both set `TEST_INJECTION=1` solely to permit the clock hook; existing failure/no-iterate hooks remain disarmed and their events are forbidden. Both explicitly set `ADAPT_THIN_CASE_LIMIT_SECONDS=900` to provide a real, bounded remaining-time stream. These test settings are written only to private workbook copies.

| Scenario | Hook called after configuration and mesh, immediately before `RPX_Run` | Required clock evidence |
| --- | --- | --- |
| W0 | `RPX_TestClockWrap 0` | Hook inactive before/after; zero simulated wraps; normal production clock path. |
| W1 | `RPX_TestClockWrap 120` | Hook active before/after, wrap threshold 120, initial wrap count zero, final count at least one, hook elapsed at least 120 seconds. The corrected Timer fallback is forced, including on 64-bit VBA. |

`RPX_TestClockStatus()` is captured before/after the run in each `worker_state.json` and `result.json`. W1 additionally requires returned `raw_jump` to be negative and `corrected_step` to be nonnegative. The intentionally negative raw jump is hook diagnostic data outside the analysis log, never an elapsed duration. The driver captures `RPX_Clock` immediately before arming and at run start/end, and compares its advancement with Python's independent monotonic wall clock. Arming must preserve the clock epoch, and W1 must not introduce an 86400-second discontinuity. The independent wall duration from starting the arm call to entering `RPX_Run`, including state-file persistence, must be at most 2 seconds.

## Mandatory automated acceptance

- Each worker must return normally with no driver, macro, settings, timeout, or cleanup errors. Require one `run_start`, exactly one final `run_end`, and `run_end.status` equal to `OPTIMAL` or `PARTIAL_CERTIFIED`. Require finite positive ordered sheet lower/upper Fs. A native/DLL result status alone is never accepted as a certificate.
- Inspect every temporal/budget field in all log columns and every semicolon-delimited detail occurrence, preserving duplicate keys. Match `seconds`, `elapsed`, `remaining`, `deadline`, `budget`, and `time` names and the legacy unitless HSD/thin budget names (`ordinary`, `floor`, `applied`, `limit`, `grace`, and time/size/cone floor/cap fields). Each numeric scalar must be present, parseable, finite, and nonnegative: examples such as `seconds=broken`, `seconds=`, or `seconds=NaN` fail. Require the numeric fields used by evaluated thin steps, native calls, and HSD/thin budget events to exist. The source/log audit identified only two textual cases among matching keys: `remaining_source` must be one of `none`, `case_limit`, `deadline`, or `nominal`; `from_budget` may carry Boolean `True`/`False`. These narrow exceptions do not exempt numeric durations. In particular inspect `thin_layer_step.seconds`, `seconds_limit`, `requested_seconds`, `packed_seconds`, and every `remaining_seconds`. No exception is made for an existing `-1` not-started sentinel: it fails this task's strict log acceptance, though it need not indicate a clock defect.
- Require all `elapsed_s` values finite, nonnegative, and nondecreasing. The full elapsed stream and measured durations must fit within the independently measured macro wall time plus 2 seconds. The 2-second allowance accommodates Timer resolution, formatted log precision, and COM read overhead; it cannot hide a midnight-sized jump.
- Require at least one evaluated `thin_layer_step` with numeric `seconds`, multiple meaningful `remaining_seconds` observations from `remaining_source=case_limit`, and at least one `thin_layer_budget`. Remaining values must not exceed the configured 900-second case limit. At every case-limit observation, require `remaining_seconds = max(0, 900 - row.elapsed_s)` within 2 seconds; a constant offset cannot pass. For successive observations, also require `current_remaining = max(0, previous_remaining - elapsed_delta)` within 2 seconds. These checks test both the absolute case clock and continuity without budget replenishment, including across the forced wrap. Logged HSD applied allowances must fit their logged available seconds, and native requested/packed budgets must fit the whole case limit. `thin_layer_budget` reports pre-clamp floors; `thin_layer_upper_hsd` and `thin_layer_lower_hsd` also log allowances before the final common clamp. These observations establish logged allowance consistency, not the final actual solver budget.
- W1 requires log rows and meaningful remaining-time observations definitely before and after the 120-second wrap, plus a solver budget observation definitely after the wrap. Compute `B = clock_at_run_end - clock_before_arm - final_run_end.elapsed_s`. Because this includes the nonnegative pre-arm/startup and post-log delays, the hook-arm-to-log-origin delay lies within `[0, B]`. Require `-0.05 <= B <= 2` seconds (the small negative margin allows Timer/log resolution), otherwise fail uncertain attribution. The wrap therefore lies within log seconds `[120 - max(0, B), 120]`. Pre-wrap evidence must precede the lower endpoint by over 2 seconds; post-wrap evidence must follow the upper endpoint by over 2 seconds. This conservative interval includes COM dispatch, state-file persistence, and internal startup delays rather than assuming the early status snapshot marks the analysis origin. Hook activation/count evidence without actual log coverage does not pass.
- Require W0/W1 settings equal with no excluded keys. Compare both certified endpoint values using the actual common `FS_TOL` from the workbook (verified as `0.0001`): `abs(W1.lower_fs - W0.lower_fs) <= FS_TOL` and the same for upper Fs. There is no user option to loosen this tolerance.

Review `repro_summary.json`, each scenario's `result.json`, `worker_state.json`, `worker.log`, and original UTF-16 `analysis.tsv`. `timing_evidence` records every inspected numeric temporal sample, remaining-time sequence, pre-clamp budget observations, hook status, the origin-delay bound and wrap interval, and any error with its source TSV row. Exit 0 means complete PASS; exit 1 means a failed acceptance check; exit 2 means only one scenario was selected and the W1/W0 comparison is incomplete. Individual scenarios cannot establish full acceptance.

## Missing coverage and follow-up

If the run finishes before 120 seconds, wraps only after the analysis has ended, lacks remaining-time observations on both sides, or lacks a post-wrap solver budget, W1 fails. Do not mark the wrap test passed, lower the wrap threshold, insert sleeps, reuse stale logs, or claim numerical validation from static checks. Record the missing coverage and, if a longer numerical workload is needed, select and document identical expanded P02A_THIN controls for both scenarios in a separate operator test revision. This driver deliberately has no automatic workload/threshold adaptation.

As additional operator checks, run a separate default-off production case with the clock hook never armed and `TEST_INJECTION=0`, verify the full project on its inherited Win64 target, and inspect first/last clock samples and repeated calls during a wrap. The new clock helper has conditional Timer-fallback branches, but the inherited project itself assumes Win64; this change does not make the whole project portable to 32-bit or older VBA. Validate those fallback branches separately in a minimal helper-only VBA harness on the relevant target. On Win64, W1 already forces the corrected Timer fallback in the production project. A real-midnight run is optional corroboration. These checks are not represented as completed by the driver or by the static deliverables.
