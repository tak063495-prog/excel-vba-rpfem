# G1R18 Issue #15 修正版（浸透の再解析失敗後に旧水頭を連成へ再利用する）

[Issue #15](https://github.com/tak063495-prog/excel-vba-rpfem/issues/15) の修正版です。基準は main `d7c3d31`（G1R18_Issue12 マージ後）。G1R18・G1R18_Issue12 は変更せず、このフォルダーに分離しています。

## 利用

- `delivery/RPFEM_G1R18Issue15_20261015.xlsm` と同じフォルダーに `rpfem_native_x64.dll`・`rpfem_accuracy_x64.dll`（G1R18 と同一）を置きます。ブックは G1R18_Issue12 配布ブックの標準モジュール `RPX_SeepUI` だけを置換したものです。
- 手動適用は G1R18_Issue12 ブックの別名コピーで `RPX_SeepUI` を `import/RPX_SeepUI.bas`（CP932/CRLF）で置換し、コンパイル・保存します。`src/vba/` は UTF-8 の編集元、差分は `changes.diff`。

## 原因

`RPX_SeepRun` は開始時に前回の「浸透結果」を無効化せず、入力検証失敗や例外では `RPX_SeepWriteResults` を通らずに終了します。そのため前回の K2=True・K9（計算ID）が残り、`RPX_Water.LoadSeepResult` は K2/K9 だけで受理するので、後続の連成Fsが新しい浸透条件に対応しない旧水頭を使っていました（冷読込・暖キャッシュとも）。

## 修正（`RPX_SeepUI` のみ）

- 浸透解析の開始時（入力読込・検証より前）に `RPX_SeepInvalidateResult` で「浸透結果」K2 を False にし、L2 に「直近の浸透解析が未完了・失敗のため連成に使えません（過去の結果）」と表示します。表示用の値（節点・要素・K9）は残します。
- 失敗終了（入力検証失敗・例外）時にも同じ処理を行います。逆推定（モード3）のように結果出力後に例外が起きた場合も連成に渡しません。
- 成功時は従来どおり `RPX_SeepWriteResults` がシートを全消去して K2（収束判定）・K9 を書き直すので、新しい結果だけが受理されます。
- `LoadSeepResult` は K2 を計算IDのキャッシュ照合より前に確認するため、暖キャッシュも K2=False で拒否されます。K2 はセル値として保存されるので、再オープン後も旧フラグは復活しません。`RPX_Water`・DLL は無変更です。

## 検証（2026-10-15、Rico 実Excel 16.0、自分で起動したプロセスのみ）

`tests/run_issue15_excel.ps1` が基準ブック（G1R18_Issue12）と修正版の別名コピーに `tests/Issue15Probe.bas` を入れて実行。各ケースは「収束済み結果を書込→（冷：計算IDを更新してキャッシュを外す／暖：直前に連成読込してキャッシュ済み）→再解析→連成読込」。結果は `results/issue15_excel.json`。

|ケース|G1R18_Issue12|修正版|
|---|---|---|
|成功→入力検証失敗（実 `RPX_SeepRun`）冷/暖|K2=True のまま、旧水頭を**受理**|K2=False、「連成：浸透解析が収束していません」で**拒否**|
|成功→未収束（WriteResults経由）冷/暖|拒否|拒否|
|成功→再成功 冷/暖|受理|受理|

※プローブのメッシュはダミーのため、受理後は下流の補間で「インデックスが有効範囲にありません」になります。判定は浸透結果読込を通過したか（受理）、`連成：浸透…` で止まったか（拒否）です。

配布ブックは置換・コンパイル・保存・再オープン後に `RPX_SeepUI` がソースと一致し、他モジュールは大文字小文字の表記差以外に変更がないことを確認（PASS）。

## 制限・未確認

- 「成功→ソルバー例外」は実モデルで例外を起こす手段を用意できず、実Excelでは未試験です（入力検証失敗と同じ `Finish` の失敗分岐を通ることはコードで確認）。
- 実斜面モデルでの連成Fs値の比較は未実施です。
- Issue 本文の「入力・形状の同一性情報で照合する」設計までは入れていません。今回は失敗・未完了の結果を連成に使わせない最小修正です。浸透入力を変更しただけで再解析しない場合に旧結果が使われる点（`RPX_Guard` の監視対象外）は既存仕様のままです。

## 再現

```powershell
powershell -NoProfile -File tests/run_issue15_excel.ps1 -BaseBook <G1R18_Issue12.xlsm> -SrcDir src/vba -OutDir <dir>
```

既存 Excel が動作中なら開始しません。
