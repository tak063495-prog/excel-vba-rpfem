# DLL4の変更と検証の対応

| 課題 | 実装 | 検証 |
|---|---|---|
| DLL_3では三角求解・DD原作用素・補正のたびにVBAへ戻る | 通常`rpfem_refine.cpp`・HSD`rpfem_hlinear.cpp`の所有ワークスペースと再開可能ジョブ | q8三版FEM、HSD6組、262144変数の途中返却・交互進行 |
| LUの圧縮因子をVBAへ書き出し、求解でDLLへ渡し直す | LUコンテキストへ因子・ワークを保持、epochで接続。製品経路で因子exportなし | 360条件の実VBA比較、LU失敗注入、切替・取消・旧版 fallback |
| 残差・方向・境界・更新の配列ループがVBAに残る | `rpfem_solver.h`のまとめた数値演算と`RPX_NativeSolver`の呼出し | 一括160、境界5070、独立物理監査、堤防全Fs探索・監査ログ比較 |
| 境界の大きい値で例外時の途中出力が変わる | 元VBAのhit・coneの途中出力を例外再送出前に反映 | 境界5070の例外・途中出力も一致 |
| 小さいLUの空U配列をnative APIが拒否する | 要素数0のUには参照されないダミーポインターを渡す | n=1/2を含むLU360条件 |
| 時計粒度が作業時間の区切りに適さない | QPCで処理時間を判定。取消は各区切り、DoEventsも維持 | 実際の途中返却、開始後の取消・入力変更 |
| 解放後のアドレスが別のジョブIDに見える | 再使用しない不透明なID、epoch・因子・寸法のチェック | 解放後ID、違うepoch/因子、二重開始・早い結果取得の拒否 |
| 切替でDLLの因子だけを破棄しVBAのreadyが残る | `RPX_NativeSetMode`で`RPX_HLURelease`し両側を無効化 | 実Excelで旧挙動のエラー9を再現、修正後は明示的な5と新分解後の成功 |
| native作業領域をLU共存メモリ予算から漏らす | 通常/HSDの保持ワークを共存見積りに算入 | 見積りの静的確認、割当失敗207、VBA7、解放漏れ検査 |
| 高速化で既存の異常を隠す可能性 | 未知・OOM・取消・添字・入力変更を保持し終了時解放。途中fallbackで隠さない | C++失敗注入、VBA12故障/完了、Issue51回帰 |

構成則・Davis・荷重・Fs・許容差・LDL/NT/内点アルゴリズムは変更していません。非線形反復とFs・監査・救済の制御は既存VBAのままです。
