# G1R16 DLL4の実装

## 演算をまとめる範囲

通常内点法とHSDの線形求解・精度補正を、状態を保持するDLLジョブとして実装しました。DLL4は、逐次の小さい演算をVBAから呼ぶ方式を避け、三角求解、行列積、残差の評価、補正、解の選択までをDLL内部で進めます。VBAはジョブを開始し、進捗の区切りで入力と取消を確認し、結果を取得します。

通常経路の`rpfem_refine.cpp`は右辺・解・残差・補正の作業配列を所有します。係数行列とLDL因子は既存VBAの所有を維持し、その呼び出し中だけ参照します。HSDの`rpfem_hlinear.cpp`はDouble/精密DD-LDL/ピボットLUの各経路に対応し、元のDD原作用素を使う反復補正、最良解と9件までの残差履歴を保持します。元の補正回数・収束条件・悪化時の停止条件を変更していません。

HSD LUは圧縮済み因子と前進・後退代入の作業領域をDLLコンテキストに保持します。通常求解では因子をVBAへ書き戻しません。`RPX_NativeLUMaterialize`は検証用の明示的な因子出力であり、製品の求解経路では使用しません。メッシュ・材料・Fsの更新による数値再分解は元の規則を維持します。作業領域の寸法一致を、行列や因子の同一性の証明として扱いません。

DLL3から継承したNT、KKT、G/G転置、DD原作用素に加えて、以下を追加しました。

- 残差全体の組立と最大値評価。
- 通常経路の右辺コーン積、方向復元、三角求解と反復補正、状態更新。
- HSDのDD方向復元、境界付き方程式のDD集約、方向のスケール変換。
- HSDの三種類の後退誤差診断の行列積と集約。
- HSDの候補状態のDD更新。監査・バックトラック後にVBAが採用します。
- コーン境界の根と内部性の判定。35回二分法などの元の選択規則を維持します。

**固定Fsの求解制御全体を一つのC関数へ置き換えた版ではありません。** Fs探索、メッシュと構成則、通常/HSDの非線形反復の分岐、監査、救済・再分解の判断、特殊なKrylov修復と境界修復の制御は既存VBAを維持しています。監査と救済が参照する状態の所有を保つため、設計を「状態を保持する演算ジョブとVBAの既存制御」に具体化しました。

## 精度の維持

演算の順序、Doubleへ格納する位置、DDのhi/lo、NTの精密化条件、ピボットと収束のしきい値を保持します。FMAや和の並べ替えによる高速化は行っていません。DLL3のx87/SSE2・旧MSVCRTの互換演算を継承し、境界の二次式と比較にもVBAの格納・比較位置を合わせたASMを追加しました。製品は呼出元の浮動小数点制御設定を変更しません。

通常の求解の一致に加え、極端な値の境界判定でオーバーフローした際の途中のhit・cone出力、空のU因子、DD残差を再スケールするときのオーバーフローを検証対象にしています。

## 状態の寿命と異常時

DLLジョブは作業配列を所有し、VBAの配列アドレスを呼び出し後まで保存しません。右辺・モデル・因子のアドレスは呼び出し時の引数です。LUとジョブのハンドルは再発行しない整数IDを使用し、解放済みIDの再利用を拒否します。ジョブには右辺の通し番号、LUには因子epochを接続しています。

解析終了・取消・失敗・バックエンド切替・因子の破棄で解放します。メモリ不足は7、未知のC++例外は513、取消は18を保持し、通常のピボット不成立へ変換しません。DLL不在・非対応版のVBA切替は開始時に行います。途中の未知例外を、VBAで再実行して隠す方式は採用していません。

HSDの保持済み作業配列はLUの共存メモリ見積りに加算します。上限を超えた場合は明示的に停止します。

## 応答と入力確認

線形ジョブは高分解能時計で約50msの処理単位を目標にVBAへ戻ります。単一の不可分な処理があるため、厳密な最大応答時間の保証値ではありません。入力確認の既存設定`HSD_STAGE_SECONDS`を維持し、`DoEvents`と取消確認を残しています。通常はExcelのイベント処理を約50ms間隔にまとめ、設定0では各区切りのイベント・入力確認を維持します。XCancelの確認は各区切りで行います。

## 互換性

ABIは`0x00160004`です。DLL3と同じDLL名を使用するため、対応XLSMとDLLの組を使います。旧DLLとの組み合わせはVBAへ切り替わります。64bit Excelを対象に実装・検証します。32bit Excelの実行を、未実施のまま合格とは記載しません。
