# G1R20 Fix1のレビュー記録

Fix1の3修正に加え、公開操作からの例外復旧、水理結果の保存・再起動、
数値・DLL・根・GAP判定の呼び出し経路を確認しました。
レビュー対象は公開Fix1の63標準モジュールと保存ブックです。

## 修正対象

1. `RPX_Setup` は内部書込みをTrueにした後の例外で元のフラグを復元せず、
   正常終了でも旧メッシュ・結果の有効フラグを落としませんでした。
   Busyも拒否しないため、解析中に入力初期化を実行できました。
2. `RPX_CreateMesh` と `RPX_Run` は、エラー処理中の失敗表示や結果消去も保護シートで
   失敗すると、VBAの有効なエラーハンドラ内で二度目の例外が起き、後始末に到達しません。
   メッシュ生成では、開始前の失敗でもEndWorkが実行され、未取得の取消設定0をExcelへ書き戻しました。
   3つの設定プリセットにも、元の設定エラーが結果失効時の保護エラーで置き換わる同型の経路がありました。
3. 水理失敗を記録するFix1のPrivateフラグは、VBAの再起動で初期化されます。
   保護された結果シートの旧K2=Trueを消せなかった失敗を保存して開き直すと、
   旧結果の再利用を拒否する記録が消失する経路が残っていました。

再現と修正後の実行は別出力に保持します。試験で用いるCurrentフラグの番兵は
状態管理の検査用であり、数値場や証明を生成したという主張ではありません。

## 数値・DLLの確認

Fs根、適応細分化、精度回復、原物理監査、証明、係数キャッシュとDLL呼出しを確認しました。
今回のレビューでは、新たな数値誤採用やGAP合格条件の不具合は確定しませんでした。
原q8・両符号・根の相対幅・モデルと入力の識別を維持します。

別フォルダーの古い同名DLLが同一Excelプロセスに先に読み込まれると、精度DLL経路を
使用できず既存VBAへ戻る場合をWindowsローダー上で確認しました。
既存の安全なフォールバックに該当し、原監査を迂回した誤採用は確認していません。
この点は今回の製品変更には含めません。

数値回帰の対象と実測値は `TEST_RESULTS.md` に記録します。
