# G1R20 Fix2 レビュー／Fix3修正

## レビュー対象

GitHub mainのFix2（`b1e092ff4a756bd6ccee84af628b494869ed515c`、PR #23）を起点に、
VBA・保存ブックの実装、浸透連成、入力変更の監視、例外復旧、旧モデル読込み、単一DLLとの境界を確認しました。
添付文書内の記載は過去の経緯として扱い、今回の依頼はFix2の不具合レビュー・修正・検証・Fix3公開です。

## 確認した不具合

1. **P1: 浸透入力を編集後、旧浸透場を使用できる。**
   mode2の水位やmode0/3の境界入力などを変更しても、旧水頭の結果ID・収束状態が残ります。
   保存／再起動でも継続し、土の計算の水圧が古くなります。
   生成時の水理依存入力をlosslessなCustomXMLレコードへ保存し、出力IDと入力値・数式・モードを照合します。
   mode0/1/2/3の生産前後・連成読込み・実行途中にも検査し、イベント無効時も拒否します。
   手動計算モードでも入力式を再計算してから検査します。
2. **P2: キャンセル後、次の浸透操作も取消扱いになる。**
   古いXCancelを新しい浸透解析・入力点検・プレビューが引き継ぎます。
   Busy判定の後で新しい操作の取消状態を初期化します。
3. **P2: 浸透入力の「書式更新」が数式を定数へ変える。**
   Value2で退避していた入力をFormulaで保持し、旧形式からのモード式移行も依存関係を保持します。
   実行中の書式更新も拒否し、実行状態を保持します。
4. **P2: 保存・再起動後、入力数式の再計算で旧解析結果が残る。**
   外部参照シートの変更で材料値が41.65→51.65になっても、旧結果表示が残留しました。
   ThisWorkbook.Openで保存入力記録を照合し、観察用スナップショットを再構築します。
   SheetChange/SheetCalculateはGuardへ委譲し、浸透入力の変更も通常結果を失効させます。
5. **P2: 旧形式ファイルのReadModelが制約コレクションを初期化しない。**
   新規ExcelのTestFs/ExactModelがエラー91となり、前モデルの制約がある場合は持ち越します。
   旧形式には制約レコードがないため、空コレクションを明示的に新規作成します。

6. **P2: DLL有効の粘着力のみのモデルが有限Fsを誤拒否する。**
   phi=0の解析的Fs計算は厳密な最適値を必要としますが、回復禁止の呼出しにもDIRECT_DLLが入り、
   値10の元dualガイドをOPTIMALと認めずNO_FINITE_POSITIVE_FSで終了しました。
   既存のallowRecovery=FalseをDIRECT経路にも伝え、この呼出しでは既存の最適値計算を使います。
   一方の証拠・ガイドを最適解として認定する変更ではありません。

変更は7標準モジュールとThisWorkbookイベントです。残る56標準モジュール、
統合DLLはFix2と同一です。ソルバー本体・物理式・原監査の許容値は変更しません。

## 保存形式と失敗時の扱い

[水理sourceレコードのAPI・スキーマ](tests/WATER_SOURCE_RECORD.md)を参照してください。
CustomXMLはUTF16LE/Base64で文字列を保存し、型・数式・IEEE doubleを保持します。
新規追加→読戻し照合→旧レコード削除の順で更新し、壊れた記録・複数記録を正常扱いしません。
従来の水理PENDING/COMMITTEDジャーナルも継続します。
生産者を直接呼ぶ場合の責任と、旧水理結果を再実行する必要も文書化しています。

数値式や監査の許容値を緩める変更はありません。バグが存在しないことの保証ではなく、
再現条件と確認範囲を証拠に基づいて示しています。
