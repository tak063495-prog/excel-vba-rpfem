# G1R17 の導入・復旧

## 配布ブックを使う

1. ZIPをローカルフォルダーへ展開します。`delivery/`のP06AまたはP06Nの設定済みXLSMと、同じ`delivery/`の`rpfem_native_x64.dll`を組で使います。
2. DLL交換時はExcelを終了してください。G1R16のブックにG1R17のDLLだけを差し替えると、ABI検査によりVBA経路に戻ります。
3. 原本を保管し、作業用ブックを別名で保存します。組織の規則に従ってマクロを実行してください。マクロセキュリティ・レジストリ・VBAプロジェクトアクセスの設定は本作業で変更していません。
4. 設定はTARGET=200、q=8、ADAPT=0、浸透OFF、kh=0です。「要素定義」の「解析」で粗メッシュ確認を再実行できます。実際のメッシュは局所修復を含め245要素です。
5. 「解析結果」の上下界と判定を確認します。保存結果は`PARTIAL_CERTIFIED`です。Fs根の探索幅と上下界の区間幅は別の値です。フル解析・細分化後の精度は今回の検証範囲外です。

DLLなし・旧ABIのDLLではVBAで計算できます。G1R17の修復はそのVBA経路にも含まれます。DLL内部のメモリ不足・未知例外・中断を、通常のDLL不在として隠していません。

確認が必要な場合、VBEのイミディエイトウィンドウで `? RPX_NativeInfo()` を実行すると、`DLL_READY`、`DLL_NOT_FOUND`、`DLL_ABI_MISMATCH`などの理由が分かります。`Call RPX_NativeSetMode("vba")`でVBA、`Call RPX_NativeSetMode("auto")`でDLL自動選択を指定できます。

## 手動でコードを導入する

通常は配布ブックを使い、手動導入は不要です。手動導入の基準は**G1R16 DLL5版の別名コピー**です。

- 既存標準モジュール`RPX_Mesh`、`RPX_Native`を、`import/`の同名ファイルで置き換えます。
- 新しい標準モジュール`RPX_NativeMesh`を、`import/RPX_NativeMesh.bas`から追加します。
- モジュール名を維持し、G1R17対応DLLを同じフォルダーに配置します。全プロジェクトをコンパイルし、保存・閉じる・再読込で確認します。

編集用`src/vba/`はUTF-8、インポート用3ファイルは実ExcelのコードページCP932・CRLFです。損失のない往復変換を検証しました。別のコードページでは対象環境に合わせて厳密変換し、置換や文字化けを認めないでください。

`ThisWorkbook`および`Sheet*`は変更していません。document moduleを標準モジュールとして追加しないでください。イベントコードの追加配置はありません。`tests/`のラッパーや試験モジュールは配布ブックへ導入しません。

## 復旧

Excelを終了し、保存しておいたG1R16 DLL5のブックとDLLを同じフォルダーへ戻します。G1R17を維持してDLLだけを退避する場合は、修復済みVBA経路を使います。途中の値ではなく、再実行後の終端判定・監査結果を確認してください。

元ブックと旧バージョン2,789ファイルのハッシュを保全しています。旧P2-Sハンドオフの32ファイルも別に検査しました。配布ブックは実Excelで変更・コンパイル・保存したものです。`vbaProject.bin`差し替えやスプレッドシートライターでの書き戻しは行っていません。
