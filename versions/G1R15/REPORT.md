# G1R15：浸透入力の整理・地下水面入力・水平震度法 ― 実Excel検証（スモーク）

2026年10月11日、ユーザーのWindows環境の実Excel（1インスタンスずつ）で確認した。全回帰（D03N全解析など長時間の計算）はまだ実施していない。

## 作成したブック
`tools/install_g1r15.ps1` で G1R14 の配布ブック（D07A・D03N）と堤防例題に導入した（元ブックは変更なし）。フック：`RPX_Mesh` 140行の直後に `RPX_SeismicBody count`、`RPX_Control` 387行の直後に `Call RPX_SeismicOverlay`。G1R14のフック2行は既存。導入時に浸透入力シートを新配置へ移行し、設定15・16行（SEISMIC_KH／SEISMIC_DIR）を追加。

## スモーク試験（浸透なし、目標200要素、メッシュ最適化OFF）
| ケース | Fs下界 | Fs上界 |
|---|---:|---:|
| D07A kh=0 | 1.222304 | 1.363964 |
| D07A kh=0.15 右(+x・谷側) | 0.979022 | 1.098599 |
| D07A kh=0.15 左(-x・山側) | 1.4130 | 1.7468 |
| D07A kh=0.25 右 | 0.8547 | 0.9645 |
| D07A kh=0.25 左 | 1.4130 | 2.1031 |
| D07A 鏡像形状 kh=0.15 左（＝原形状の右に対応） | 0.9834 | 1.0967 |
| D03N kh=0.15 右 | 0.258423 | 0.848328 |

- 谷側向きでFsはkhとともに単調に低下、山側向きでは上昇。
- 鏡像形状での向き反転は原形状と0.5%以内で一致（差はメッシュの違い）。
- kh=0 は `RPX_SeismicBody` が何もしない（体積力に触れない）。
- 山側向きの下界1.4130が kh=0.15〜0.4 で変わらないのは、粗いメッシュ（200要素・最適化OFF）で天端の上載荷重端付近の下界が頭打ちになるため。最適化ON・目標600要素の kh=0.25 左では下界1.876→1.930（上下界差2.8%）まで改善した。
- D03N 200要素・最適化OFFは上下界差が大きい（参考値。D03Nは本来1536要素・最適化ONで使う）。

## メッシュ最適化ONでの kh=0／kh=0.15 比較（D07A、浸透なし、目標600要素、他設定同一）
| 段階 | kh=0：経過秒／下界／上界 | kh=0.15右：経過秒／下界／上界 |
|---|---|---|
| coarse_0（270要素） | 0–150s／1.2256／1.3660（差10.8%） | 0–96s／0.9808／1.1026（差11.7%） |
| adapt_1_band（270要素） | 150–216s／下界0.559（改善なし gain=0） | 96–170s／下界0.233（改善なし gain=0） |
| band_refine（314要素） | 217–320s／1.2504／1.3370 | 170–489s／1.0041／1.0778 |
| staged_refine | 320–543s／1.2589／1.3026 | 489–724s／1.0099／1.0486 |
| final（下界600／上界270要素 → kh=0.15は597／270） | 543–709s／**1.263407／1.281665**（差1.43%） | 724–909s／**1.013676／1.031551**（差1.75%） |
| 合計計算時間 | 709秒 | 908秒 |

- 最適化の段階（band → band_refine → 赤緑細分化 → final）、要素数（270→314→上限600）、採用メッシュはkh=0と同一。最終の上下界差も1.43%と1.75%で同程度。「最適化が進まない」現象は確認されなかった。
- 計算時間が約1.3倍になった主因はband_refine段の下界Fs探索（kh=0.15で319秒、kh=0で104秒）（下界Fsの試行回数が増えたことによる。原因の詳細は未調査）。
- adapt_1_band で下界が改善しない（gain=0）のは kh=0 でも同じで、地震追加による変化ではない。
- コード上の確認：地震力は `RPX_AssignRegions`（再メッシュ・細分化・面分割のたびに必ず呼ばれる）で自重と同時に「上書き」で設定するため、再メッシュ後の付け忘れ・二重加算は起きない。連成ONでは `RPX_WaterApply` が体積力を作り直した後に1回だけ加算。誤差指標（`RPX_Indicator`）・細分化（`RPX_Refine`）は体積力を参照しない。適応状態の保存・復元（`RPX_Adapt` 159/300行）は体積力配列ごと保存するので整合。

## 修正した不具合
- 地震表示に図形（テキストボックス・矢印）を使うと、解析直後の再描画でExcelが異常終了（0xc0000005）する例があった。図形をやめ、`図`M1セルの文字表示に変更して解消（同条件で再現なし）。
- 浸透入力のMsgBoxがCOM自動実行を止める問題に静音スイッチを追加。

## 制限・注意
- 水平震度法は擬似静的。鉛直震度、地震時の過剰間隙水圧、動水圧は扱わない。khは全要素一様。
- 地震慣性力は全単位体積重量γ（飽和部も）× kh。連成ONでも水の慣性は別扱いしない（土＋水の全重量に作用させる一般的な扱い）。
- 水平体積力があると、鉛直自重のみを前提とした高速化経路（c=0直接候補 `RPX_DirectC0Candidate`、φ=0候補 `RPX_Phi0QCandidate`）は自動的に対象外となり、通常経路で解く。
- 剛体要素にも kh·γ を作用させる（水圧は従来どおり作用させない）。
- G1R14の制限（浸出点の過小傾向、推定すべり面は可視化であること等）は継続。
- 長時間のCOM呼び出し（Application.Run）ではRPC切断を観測した例がある。Excelは1つだけで実行すること。
