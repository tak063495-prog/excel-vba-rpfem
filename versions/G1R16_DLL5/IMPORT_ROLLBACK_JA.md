# DLL5 の導入・復旧

## 通常の利用

1. DLL5のZIPをローカルフォルダーへ展開します。`delivery/`の`RPFEM_20261012_G1R16_DLL5_Levee_Checked.xlsm`と`rpfem_native_x64.dll`を組で使用します。
2. DLLを交換する際はExcelを終了し、読み込み済みDLLが残らない状態で交換します。DLL4のブックにDLL5だけを差し替えないでください。
3. `SHA256SUMS.txt`でファイルを確認し、組織の規則に従ってマクロを実行します。DLLは64bit版Excel用です。通常の解析にPython・VBAプロジェクトアクセスの許可は不要です。
4. 原本を残して作業用ブックを別名で保存します。堤防例題の設定と計算結果が入っています。入力を変更する場合は「材料データ」「要素定義」「設定」「浸透入力」を確認してください。
5. 「要素定義」の「解析」を実行します。必要に応じて先に浸透解析・図表示を確認します。判定と根幅・GAPは「解析結果」および解析ログで確認してください。

DLLが存在しない場合、非対応ABIの場合、32bit環境では従来VBAを選びます。DLL不在、DLL2、DLL3、DLL4の非対応DLLと、明示VBAモードの復帰は試験しています。VBAに切り替わると時間は長くなります。DLL内の未知例外・実際のメモリ不足・取消を通常のVBA切替として隠しません。

バックエンドを確認する場合、VBEのイミディエイトウィンドウで`? RPX_NativeInfo()`を実行します。利用可能時は`DLL_READY`、不在・非対応時には理由を表示します。`Call RPX_NativeSetMode("vba")`で従来VBA、`Call RPX_NativeSetMode("auto")`でDLLの自動選択を指定できます。

## 手動でソースを導入する場合

配布XLSMは実Excelで導入・全プロジェクトのコンパイル・保存・再読込を確認済みです。通常は手動導入不要です。

手動導入する場合は、**G1R16 DLL4の別名コピー**を使い、既存標準モジュール`RPX_Conic`、`RPX_Guard`、`RPX_Native`、`RPX_NativeBulk`、`RPX_NativeSolver`、`RPX_Schur`、`RPX_SchurLDL`、`RPX_Solve`をそれぞれ置き換えます。新しい標準モジュール`RPX_NativeGuard`を追加します。モジュール名を変えないでください。

VBEへのインポートは`import/`の9ファイルを使います。編集用の`src/vba/`はUTF-8です。実Excelの対象コードページCP932とCRLFへ厳密変換し、往復一致・損失なしを確認したインポート用ファイルを用意しています。別言語環境のVBEでは対象エンコーディングを確認し、文字化けや置換があれば導入しないでください。

`ThisWorkbook`と`Sheet*`のdocument moduleは変更していません。これらを新しい標準モジュールとしてインポートしないでください。イベントコードの追加配置はありません。VBEで全プロジェクトをコンパイルし、ブックを保存して閉じ、再度開いて`DLL_READY`とボタン操作を確認します。

VBAプロジェクトアクセスの許可・マクロセキュリティ・レジストリを本作業で変更していません。再導入ツールは利用者がすでに認めているネイティブExcelの環境を前提とします。

## 復旧

Excelを終了し、保存したDLL4ブックとDLL4を同じフォルダーに戻します。またはDLL5の組を維持したままDLLをフォルダー外へ退避し、VBA経路で解析します。途中結果を最終のFsとして使わず、復旧後の終端判定を確認してください。

元ブック・旧バージョン・入力カタログは保全しています。1085ファイルのハッシュ検査と旧P2-Sパッケージの32項目検査を別々に記録しています。ブック内部の`vbaProject.bin`差し替えやスプレッドシートライターによる書き戻しは行っていません。
