# DLL5 の実装範囲と精度を保つ方法

DLL4を基準に、予定していた主要な追加最適化をDLL5へまとめました。通常内点法とHSDの両経路が対象です。Fsの定義、Mohr–Coulomb、Davis変換、上下界の定式化、荷重・水圧・地震、物理監査、収束条件・ピボット条件・救済順序は維持しています。あらゆる入力に対する最速性や、将来改善が不要になることを保証するものではありません。

## 変更とボトルネックの対応

| 対象 | DLL5の変更 | 精度・ロバスト性の保護 | 対応ソース |
|---|---|---|---|
| 入力同一性の確認 | Excelから取得したVariant配列の意味をDLLで比較 | 種別・文字列・数式・CVErr・Emptyを区別。比較範囲・頻度を維持。対応外は元のVBA比較 | `RPX_Guard`、`RPX_NativeGuard`、`rpfem_guard.cpp` |
| 疎パターン準備 | Dictionaryの挿入順に対応した型付き構造、署名作成、順列反映、CSC/slot生成をDLL化 | 署名の全文、並べ替え・同順位の順序、Fs間の既存パターン/順列再利用を維持。数値因子を誤再利用しない | `RPX_Conic`、`rpfem_compile.cpp` |
| Schur経路 | 局所3×3反転、Schur更新、縮約求解、完全系残差と3回の補正を状態付きDLLへ | 同じ演算順、4回の検査、既存1e-11の判定、再計算/REUSE_U/COMPAREの条件を保持。所有バッファと予算を管理 | `RPX_Schur`、`RPX_SchurLDL`、`rpfem_schur.cpp` |
| HSDのDD組立 | 原作用素のDD組立、対角正則化、スケーリングを一括処理 | DDの加算順・係数split・±1e-10の正則化を維持。元作用素の検査を保持 | `RPX_Solve`、`rpfem_hdd.h` |
| HSDのKrylov修復 | 前処理付きGMRESの内部反復全体をDLLで継続 | 幅24・再開3・2回MGS・補償内積・最良解の保存・DD作用素による1e-11受入条件を保持 | `RPX_Solve`、`RPX_NativeSolver`、`rpfem_krylov.cpp` |
| VBA/DLL間の往復 | 既存の演算チャンクを時間区間ごとにDLL内部でまとめる | DoEvents、入力変更確認、取消、段階タイムアウトを維持。特殊な厳格試験では既存チャンク境界を使用 | `RPX_Native`、`RPX_NativeBulk`、`RPX_NativeSolver`、`rpfem_batch.cpp`、`rpfem_batch_bulk.h` |
| DD演算内の細かい関数呼出し | DD加算・乗算を組み合わせたアセンブリ処理 | 元のDouble格納/丸め境界を保持。FMA・fast-math・再結合なし。異常値の拒否順序も比較 | `vba_fp.asm`、`rpfem_native.c`、`rpfem_bulk.h` |
| 疎Double演算内の関数呼出し | 行列列内のscatter/gatherをアセンブリでまとめる | 元の行順、1要素ごとのDouble丸め、有限値検査、異常時の途中出力を維持 | `vba_fp.asm`、`rpfem_native.c` |
| HSDの状態の同一性 | 長さで区切った配列をIEEE754のビットで比較 | 丸めたキーを同一性の証明に使わない。HSD状態は符号付き0・NaN payload・1ULPの差も検出 | `RPX_Solve`、`rpfem_batch.cpp` |

## 所有権・中断・例外

状態付きジョブはDLL所有の配列と不透明なIDを使い、VBAの配列アドレスを呼出し後まで保存しません。借用する配列は各呼出しで渡し直します。パターン・数値因子の世代とジョブのserialを検査し、解放済み・不一致・再入を拒否します。SAFEARRAYは呼出し中だけロックし、正常・異常とも解除します。モード切替と失敗時には当該ジョブを解放します。

VBAに戻る時間区間の目安は通常約50msです。既存の演算チャンクが終わってから戻るため、50msを必ず下回る保証ではありません。チャンクの内部処理を1回の呼出しへまとめ、VBA/DLL受け渡しを減らします。DoEventsを削除して高速化する設計ではありません。

メモリ不足、配列添字、取消、未知例外、入力同一性違反は伝播・記録します。既知の容量制約で従来経路を選ぶ処理と、実際のメモリ不足を握りつぶす処理を区別します。今回のC++障害試験は試験用実行ファイル内で注入し、配布DLLへ故障注入機能を組み込んでいません。

## 残るVBA処理

外側のFs探索、固定Fsでの非線形反復の制御、救済方針、監査、メッシュ適応、物理モデルの生データ組立、Excelシート入出力はVBAに残しています。これらの定義や順序を変えて速度を稼ぐ方法は今回採用していません。モデル準備については疎構造の組立・並べ替え・slot生成を追加移植しましたが、有限要素の物理係数計算全部を移植したわけではありません。

## ソース・ABI・ビルド

基準はG1R16 DLL4、commit `6f9c2248945f2cda25fd3a04b40ab962a70187bf`です。旧69モジュールのうち8を変更し、`RPX_NativeGuard`を1つ追加した70モジュール構成です。既存61モジュールと全document moduleは変更していません。`changes.diff`と`native_changes.diff`はDLL4との差分です。

DLL5 ABIは`0x00160005`、Windows x64です。`native/build.cmd`はVisual Studio 18 BuildTools・MASMで、`/O2 /fp:strict /MT /W4 /WX`を使用します。浮動小数点の制御ワードは呼出し元の設定を維持します。Python単体比較では実Excelの設定を観測して、そのPython試験プロセスだけを合わせます。

既存のライセンス表記を維持しています。適用条件と第三者コードの注意事項は`native/licenses/`を参照してください。数値核のソース・ビルド手順・試験は配布ZIPに含みます。
