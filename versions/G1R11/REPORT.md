# G1R11 実装・検証報告

P06N用の改訂版 `RPFEM_20261007_G1R11_P06N_Staged_1000.xlsm` を、G1R10の保全済み原本から別ファイルとして作成しました。VBA実装前にPythonで候補メッシュ・固定Fs・探索制御を検証し、その後Excelで実装と試験を行いました。

## 改善理由

提供ログ `20261007_054059_19848_analysis.tsv` のG1R10は、全61求解がOPTIMAL、監査732件がPASSでした。ただし全解析は44,471.36秒（12時間21分11秒）で、G1R9の23,952.24秒に対して85.67%増加しました。Fsは下界0.613174343906005、上界0.711569340880918、GAP14.8549%、1536要素、PARTIAL_CERTIFIEDです。

G1R10の実行経路は601→902→1348→1536要素への直接細分化で、以前のPython検証の土台だった「従来の再配置後781要素」と異なっていました。初期601要素の18求解はG1R9とログ上完全一致しています。数値核の変更による初期不一致より、メッシュ経路の変更と規模拡大が主な改善対象です。ログだけの比較では保存場の厳密な入力同一性を認証できないため、異なる実行のFsを合成して新しい認証区間にはしていません。

## 実装

|対象|変更|目的・保護|
|---|---|---|
|RPX_Adapt / RPX_Refine|LEGACY_THEN_REFINEを追加。従来の再配置と800要素以下の従来細分化を先に実行し、その後の赤緑細分化を最大1回に限定|実績のあるメッシュを土台にし、直接1536要素まで成長する既定経路を外す|
|RPX_Refine|明示的なforceLegacy引数を追加|新設定下でも前段の分割方式を確実に従来方式へ固定。全体の設定を一時的に書き換えない|
|RPX_Adapt|追加細分化の予算をmin(ADAPT_REFINE_CAP, TARGET)に制限。既定1000要素|1回の求解が大きくなりすぎることを抑制。既存メッシュを縮小する機能ではない|
|RPX_Fs|同じモデル版・積分次数の監査済み上界端点を、下界探索の試行位置の目安として使用|下界の符号は実求解。符号が正のままなら従来の拡張探索へ戻す。既知の数値失敗でも従来探索へ戻す|
|RPX_Fs|使用土材料が2種類以上の場合に限定。LEGACY_THEN_REFINEでは800要素以下を対象外にする|前段のFsとメッシュ生成に使う場を維持。単層・剛体の探索は従来通り|
|RPX_Adapt / RPX_Fs|追加候補の既知失敗を復元し、監査済み保存場を保持。停止対象は再送出|キャンセル、監査失敗、容量不足、配列範囲、未知例外を通常の不採用として隠さない|

変更した標準モジュールはRPX_Adapt、RPX_Refine、RPX_Fsの3つです。構成則、Davis変換、上下界組立て、荷重、物理監査、NT/HSD/LDL、順序付け、コールドスタート、G1R9のDD高速化、根探索の終了判定・許容誤差は維持しました。ThisWorkbookとSheetイベントも変更していません。

設定済み値はB48 `ADAPT_MESH_POLICY=LEGACY_THEN_REFINE`、B49 `ADAPT_REFINE_CAP=1000`、B50 `FS_BRACKET_POLICY=AUDITED_UPPER_LIMIT`です。TARGET=1536、ADAPT=1、CYCLES=3、GAP=0.01、QUADRATURE=8、FS_TOL=0.0001を保持しています。P06Nの材料、形状、ψ=0、DAVIS_EQUIVALENTも原本と一致しています。

Pythonの1000要素・下界Fs=0.66ではClarabelがNumericalError、上界Fs=0.77ではAlmostSolvedを返しました。返された場の原式監査を証拠として残しており、OPTIMALや全Fs根の合格へ読み替えていません。

実Excelでは、VBAが生成した1000要素メッシュの実際の順序で次の固定点を求解しました。

|試験|目的値|反復数|所要時間|独立監査|
|---|---:|---:|---:|---|
|P06N下界 Fs=0.655、q=4|1.01388979063567|38|1394.22秒|PASS。単位参照荷重へ正規化した場も50桁で監査PASS|
|P06N上界 Fs=0.77、q=8|0.979294074891999|55|465.16秒|PASS|

独立監査の最大残差は下界の釣合い1.40e-11、上界の参照仕事4.97e-11でした。単位荷重の50桁下界監査の最大原式残差は2.76e-10です。50桁監査は保存されたbinary64場の数値検査であり、厳密な実数区間証明ではありません。

これらは固定Fsでの証拠です。0.655–0.77の区間GAPは16.14%で、目標1%には届いていません。実際の適応解析では、その時点の上界場から指標を作るため、検証用メッシュと常に同一になるとは限りません。G1R10の最終上界0.711569を再現・改善したとは主張しません。

小規模単層試験のFsは下界1.56479461074022、上界2.16424040585209、下界19求解・上界39求解で一致しました。単層を新しい探索対象から除外し、試作段階で見られた余分な1求解を防いでいます。この小規模モデルの値をP06Nの値として使っていません。

## 確認が必要な点

今回の実装は、規模の拡大を制限し、従来の良いメッシュ経路を保持することで時間短縮を図っています。全解析の短縮率は未測定です。追加段階そのものの費用があるため、G1R9より短いことやGAP1%到達を保証できる結果はありません。GAPや監査許容差を緩める変更はしていません。全実行の手順はTEST_PROCEDURES.mdに記載しました。

設定B48とB50をともにLEGACYへ変更すると、追加細分化と新しい試行範囲制御を停止できます。保存場の採否と最終認証は既存の判定を使い、未達ならPARTIALとして報告します。
