## 変更内容（`RPX_Adapt.bas` の薄層チェーンの中だけ）

新しい処理は、薄い層の判定（`Fix8ThinMode`）が働き、チェーンの段を実行している間だけ有効になります。監査、根の規則、証明書、q8、`FS_TOL` は変えていません。

1. **中央線を独立した最初の段にする**（`ADAPT_THIN_MID_SEPARATE`、既定 1）：各チェーンの最初に、薄い材料の中央線の辺だけを分割し、そのメッシュで通常どおり根を求めます。その後の段では中央線を入れません。この段が失敗したときは、Fix8 と同じ方法（1段目にまとめて入れる）に戻ります（ログ `thin_layer_mid_fallback`）。この段はラウンド数に数えません。
2. **下界の指標を、下界メッシュ上の上界の解から作る**（`ADAPT_THIN_LOWER_OWN_UPPER`、既定 1、`_FACTOR` 既定 1.08）：DLL で1回だけ解きます（根は求めません）。この解は指標にだけ使い、結果（witness）にはしません。失敗したときは Fix8 の方法に戻ります。
3. **入替えの前に上界を解き直す**（`ADAPT_THIN_FLIP_FRESH`、既定 1）：細分したメッシュで上界を DLL で1回解き、その速度で辺を入れ替えます。失敗したときは Fix8 と同じく前の速度を写して使います。
4. **下界の根が1回決まらなくても止めない**（`ADAPT_THIN_LOWER_RETRIES` 既定 1、`ADAPT_THIN_RETRY_THETA_FACTOR` 既定 0.5）：同じ系列から、選ぶ割合を半分にして1回やり直します（ログ `thin_layer_retry`）。要素数の上限超過、取消し、致命的な誤りではやり直しません。
5. **チェーン内の HSD の時間上限を規模に合わせる**（`RPX_Solve.bas`、`ADAPT_THIN_HSD_*`）：min(3600, 1.5×(20＋0.0037×錐の数)) 秒まで引き上げます。下げることはありません。回復用の求解には使いません（ログ `thin_layer_budget`）。
6. **チェーン内の上界の DLL 直接求解の時間上限を規模に合わせる**（`RPX_AccuracyNative.bas`、`ADAPT_THIN_DLL_*`）：max(DIRECT_DLL_SECONDS, min(600, 3×3.45×(錐の数/22741)^1.2)) 秒です。

係数は、Winmax2 の Fix8 rc2 のログから求めた見積りの式です（`validation/G1R20_Fix8_p06sim_20261019/sim/vba_timemodel.py`）。

### 確認で直した点（Codex の案から）

- HSD の時間上限の引き上げを、回復用の求解（`recoverySeconds` > 0）には使わないようにしました（Fix8 の時間の下限と同じ扱い）。
- 中央線だけの段は選ぶ割合を使わないので、やり直しをしないようにしました。失敗したときにチェーンを止めず、Fix8 の方法に戻すようにしました。

Codex への指示と Codex の報告は `validation/G1R20_Fix9_optest_20261019/codex/` にあります（`TASK.md`、`CHANGES.md`、`ANALYSIS.md`、`diff_summary.txt`）。

## P06N/P06A：未検証（Python の予測では P06N は 2% に届かない見込み）

VBA では P06N/P06A を実行していません。box の Python で Fix9 のチェーンを再現した結果は次のとおりです（`validation/G1R20_Fix8_p06sim_20261019`）。
