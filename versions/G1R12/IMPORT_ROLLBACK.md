# G1R12 の利用・反映・復元

通常は完成 `RPFEM_20261009_G1R12_P06N_IssueFix.xlsm` をコピーして使います。G1R11と同じP06Nの入力・設定です。全解析未実行なので、旧結果をG1R12の計算結果として扱わず、解析後のログとブックを別名保存してください。

## 手動反映

1. G1R11原本を保存し、作業コピーを作成します。元XLSMのSHA-256は `5cb56fc51ceb21e24d3cea999a1535f91c6d983a51211873059c9c9494d454f9` です。
2. VBEで既存の `RPX_Control`、`RPX_Output`、`RPX_Robust` をバックアップします。重複モジュール名を作らないよう既存の標準モジュールを削除してから、`import_cp932/` の同名3ファイルを取り込みます。
3. デバッグ→VBAProjectのコンパイルを実行し、`.xlsm`で保存します。UTF-8の `src/` をそのままVBEにインポートしないでください。importはCP932・CRLFで、厳密に往復照合しています。
4. ThisWorkbook、Sheetコードは今回変更していません。これらを標準モジュールとして新規取り込みしないでください。試験probeも製品へ取り込みません。

完成ブックの通常利用にVBAプロジェクトへの信頼アクセスは不要です。コードを自動反映する検証スクリプトだけは、既に利用可能なVBEアクセスが必要です。スクリプトは信頼設定・レジストリ・マクロセキュリティを変更しません。利用できなければ手動コンパイルと手順に従った試験を行います。

## 復元

最も確実なのは保管したG1R11原本へ戻すことです。モジュールだけを戻す場合は作業コピーの変更3モジュールを削除し、`rollback_cp932/` の3ファイルを同名で取り込み、コンパイル・別名保存します。復元後はG1R12の結果や図を混ぜず、解析を再実行してください。rollbackはG1R11への復元です。

vbaProject.binの置換やスプレッドシートライターによるXLSM再構成は行っていません。完成ブックは実Excelの別コピーへ統合・保存しました。
