# G1R12 — GitHub Issues #1 / #2 の修正・検証

2026年10月9日。G1R11を保全し、別ファイル `RPFEM_20261009_G1R12_P06N_IssueFix.xlsm` を作成しました。P06Nの材料・入力・解析設定はG1R11と一致します。全P06N解析はこの配布ブックでは実行していません。

## 指摘の判定と修正

両Issueは妥当でした。対象コミット以後の説明資料追加でもVBAは変わっておらず、現行mainのG1R11でも成立します。

|Issue|実コードで確認した原因|G1R12の変更|
|---|---|---|
|[#1](https://github.com/tak063495-prog/excel-vba-rpfem/issues/1)|最良区間のメッシュを残したまま、独立に選んだ最良上界の速度場を現在の要素数で出力する。上界の復元は場の出力後だった|`RPX_Control`でメッシュ表・図を出す前に最良上界の完全なwitnessと場を復元する。`RPX_Output`でモデルの厳密同一性、入力epoch・政策・q・係数・スケール、場の次元と所有者の値を検査。下界は下界witnessのメッシュと場で別出力し、最後に上界へ戻す|
|[#2](https://github.com/tak063495-prog/excel-vba-rpfem/issues/2)|実際の因子分解エラーは`NEWTON_FACTORIZATION_FAILED pivot=123`の形式。救済条件は接尾辞なしの完全一致のみ|`RPX_Robust`で既存トークンに加え、正確な接頭辞とLong範囲内の符号付き十進整数を持つ形式だけを認める。部分一致・任意の接尾辞は認めず、元の詳細メッセージを保持する|

支持力では上界witnessを復元した後に集計面を計測し、旧メッシュで作った集計キャッシュを新メッシュで使わないようにしました。`RPX_WriteFields`の入口は誤った所有者を黙って置換せず、不一致を停止させます。

変更した本体は `RPX_Control.bas`、`RPX_Output.bas`、`RPX_Robust.bas` の3つです。残る43モジュールはG1R11と同一です。構成則、上下界離散化、Davis変換、荷重変換、物理監査、LDL/NT/HSDの数値カーネル、許容誤差、cold-start、既存の細分化・探索政策は変更していません。
