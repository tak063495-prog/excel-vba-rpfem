# 不具合と修正の対応

| 問題 | 実装 | 検証 |
|---|---|---|
| D03N：大きい速度場で仕事の正負項が相殺し、加算と仕事正規化が不正確になる | `RPX_WorkPrecision`でDD積和による物理仕事を再構成。`RPX_Audit`から純c=0・参照荷重モデルに限定して使用 | 元の棄却場、実VBAで正規化した場、修正版の単点場を独立50桁・正確な有理数積分で比較 |
| 仕事だけを変えるとfield/x/slack/証明が不整合になる | `RPX_HSDCandidate`で候補をtransactionとして正規化。元の等式・円錐をDD検算し、全物理監査後にcommit | 元候補のネイティブ対照、停止点の実Excel再求解、最終保存場の再監査 |
| 一般の最適性証明へ正規化を無条件に流用する危険 | 厳密にゼロの原目的・円錐offset、c=0、固定荷重0、剛体なし、参照荷重段階を要求。零双対で定数ゼロ目的の実行可能場を証明 | 静的適用ゲート、元場の非合格を維持する対照、制限外の対照 |
| D03N：候補棄却後のLDL DD積が指数範囲外になり停止する | DD/LDLのunderflowガードは保持。Fs試行中の厳密な既知エラー5だけをUNKNOWNへ分類し、既存の限定近傍点探索へ進む | 実際の`TryFsValue`に失敗注入。UNKNOWNでは値/場を採用しない。7・9・18・監査失敗・未知例外・類似トークンは停止 |
| D07A：荷重段差節点の2三角形fanで境界応力と内辺の連続条件が矛盾する | `RPX_LoadStepMesh`で直線境界の2fanと荷重差・内部辺方向を判定し、2親三角形を重心で6子三角形へ分割。領域・境界を再割当て | 実Excelの原553→557要素、314→316節点。荷重反転・等荷重・無荷重・縦内辺・回転・固定境界の対照、容量/取消/添字/荷重段階の失敗注入 |
| 局所修復後の古いメッシュキャッシュや荷重段階の混用 | `RPX_Mesh`の領域割当てでraw段階を明示し、局所修復後に再割当て。修復時にFsブラケットを無効化。既存の完全モデル同一性・下界cache規則を維持 | 25ケースの実メッシュ完全比較。変更はD07Aだけ。他24ケースは座標・材料・荷重込みで完全一致 |

元の0945/P2-SのAGENTS.mdは歴史的パッケージの保全条件として確認した。今回の修復対象は継続中のG1R12 D03N/D07Aであり、0945原版のF01〜F07を再実装する作業やP3を追加する作業へ置換していない。古い`baseline/`・`reference/`と25件のExcel受入れ台帳は変更しない。

構成則、Davis変換、上下界定式化、荷重値、LDL/NT/HSDの方向計算、既存の許容差、cold-start方針、DoEventsは保持。既存46標準モジュールのうち変更は4、追加は2、残り42は全文一致。
