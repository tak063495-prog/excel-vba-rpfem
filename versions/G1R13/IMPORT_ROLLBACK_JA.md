# G1R13：インポートと復旧

配布する修正版XLSMには実装済みコードが入っている。通常はインポート作業は不要。元G1R12ブックは保存したまま、対象ケースの修正版を開き、入力表・材料表・設定を確認して既存の解析ボタンを使用する。

## 既存ブックへ手動で反映する場合

1. 既存ブックを別名で保存する。対象はG1R12の同一系列。0945原版等へ6ファイルだけを適用しない。
2. `src/vba/`はUTF-8編集用。VBEへのファイルインポートには`import/`のCP932・CRLF版を使用する。変換はstrictで検査済み。異なるプロジェクトのコードページへ無理に変換しない。
3. `RPX_Audit`、`RPX_Fs`、`RPX_HSDCandidate`、`RPX_Mesh`の既存標準モジュールをバックアップして置換する。モジュール名を維持する。
4. 新規標準モジュール`RPX_WorkPrecision`と`RPX_LoadStepMesh`を追加する。他の42標準モジュールは同梱した元のG1R12内容を維持する。
5. VBEの「デバッグ→VBAProjectのコンパイル」を実行し、`RPX_TestHSDPrecision`を実行する。D03N/D07Aの設定済みブックによる結果・監査との照合手順は修復報告を参照する。

ThisWorkbook・Worksheetの9文書モジュールと`RPX_WitnessPayload`クラスのコードは変更していない。文書モジュールを新しい標準モジュールとしてインポートしない。`BatchEvidence`、`RepairProbe`等は試験専用で、配布する製品XLSMには含めない。

VBAプロジェクトへの信頼アクセスやマクロセキュリティ、レジストリを自動変更する手順はない。ブックはExcelの通常のマクロ運用方針に従って開く。

## 復旧

元のG1R12ブックを開くことで変更前へ戻せる。コードだけを戻す場合は、4既存モジュールを`before/vba/`の内容へ戻し、2新規標準モジュールを削除してコンパイルする。UTF-8の原ソースを直接VBEへファイルインポートする場合の文字化けに注意する。必要なら損失のないCP932・CRLF変換を行う。

変更した入力や結果を元ブックへ混ぜて上書きしない。荷重変換済みの解析メモリを、未変換の入力としてコピーしない。保存したXLSMの再開後は、再計算する場合は通常の解析入口から実行する。
