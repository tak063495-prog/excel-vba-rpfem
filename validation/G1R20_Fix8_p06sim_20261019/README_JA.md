# Fix8 の薄層チェーンを Python で再現した P06N / P06A の検証と、2% 到達までのロードマップ（2026-10-19、ローカルのみ）

VBA の P06A / P06N は実行していません。`sim/vba_chain.py` は、G1R20 Fix8 rc2 の `Fix8ThinLayerChains` を、実装どおりの既定値で Python に移したものです。

- 上界：θ 0.8、上限 3500 要素、10 ラウンド。方向性の 1 辺分割に、初回だけ中央線を加え、その後に入替えを 5 パス行います。
- 下界：チェーンのラウンド 2〜4 で行います。θ 0.9、上限 4000 要素。混合指標（背景 0）で赤分割し、初回だけ中央線を加え、その後に扇形の細分を入れます。
- 停止規則：2 回続けて改善しなかったとき、上限を超えたとき、根が決まらなかったときに、その側のチェーンを止めます。
- 根の決め方：q8 の全監査を通った場だけを使い、幅は 1e-4 です。HSD の下限時間はチェーンの中では使いません。

求解には box の Clarabel を 1 スレッドで使いました。`sim/vba_chain.py` は Python 試作のフォルダ `validation/G1R20_P06_meshproto_20261018/proto` を読み込みます。このフォルダはまだ公開していないため、このリポジトリだけではスクリプトを実行できません（結果の `results/` は読めます）。表の時間は Python の値で、並列に走らせているので速度の比較には使えません。

### 分かったこと

1. **P06A は、時間の制約を外せば、今の実装の既定値のままで 2% を下回りました**（1.83%）。下界の上限を 8000 にすると 1.64% でした。
2. **P06N は、どの変種でも 2% に届きませんでした**（最良は 2.19%）。上界の 0.68961 に対して 2% にするには、下界が 0.67595 以上必要です。チェーンの下界の最良値は 0.67557（6445 要素）で、試作（0.67670、3528 要素）より悪い結果でした。
   - 原因の一つは、下界のラウンド 2〜4 が、まだ粗い上界（約 1400 要素）の機構を使って細分していることです。
   - もう一つは、θ0.9 だと 1 ラウンドで要素数が約 1.7 倍に増え、ラウンド 3 で上限 4000 を超えて、下界のチェーンが止まることです。
   - 上界も、Fix8 の方向性細分では試作の約 2 倍の要素が必要でした（0.6896 に 4946 要素。試作は 2575 要素）。
3. **下界の根が決まらない事例がありました**（1241〜3516 要素）。Clarabel が NumericalError を返し、物理監査も不合格でした。目的関数の値自体は根の近くでほぼ正しく出ています。この失敗は Python のソルバー固有の可能性があります（VBA には HSD への切替えがあります）。ただ、今の停止規則では、1 回の失敗で下界のチェーンが最後まで止まってしまいます。
4. **粗いメッシュからすぐにチェーンを始めると、P06A は 2% 以内になりました**（1.91%、下界 θ0.7）。今の流れで標準の細分（Triela で約 4.5 時間）を経由するより大幅に短くなる見込みです。P06N では下界が止まり 3.10% でした。

## VBA の時間の見積り（`sim/vba_timemodel.py`）

Winmax2 の Fix8 rc2 のログを使って較正しました。

- **DLL**：上界は 22741 錐で 3.45 秒（P02A_THIN）、下界は 6198 錐で 2.55 秒。どちらも錐の数の 1.2 乗に比例すると仮定しました。
- **VBA の 1 回の求解ごとの処理時間**：上界は 22741 錐で 6.9 秒、下界は 6198 錐で 13.3 秒（錐の数に比例すると仮定）。
- **HSD（上界）**：20 秒 + 1 錐あたり 3.7 ミリ秒。P10A rc2 の値（41k 錐 180 秒、66k 錐 261 秒、90k 錐 353 秒）から求めました。
- **HSD（下界）**：DLL の 4 倍と仮定しました（未較正）。
- 1 段階あたりの求解は 13 回としました（VBA のログでは、新しいメッシュ 1 つにつき 12〜13 回）。

- **DLL が 5 秒（DIRECT_DLL_SECONDS）を超える境目**：約 31k 錐。P06N の上界ではおよそ 960 要素です。Fix4 の bench26 で観測した「961 要素までは DLL で解け、それより大きいと HSD に切り替わる」とよく合います。

## ロードマップ（優先順。どれも未実装・VBA では未確認）

1. **上界は DLL 直接で解く（一番効果が大きい）**
   - `DIRECT_DLL_SECONDS` を固定の 5 秒から、規模に合わせた値に変えます。例：max(5, 3 × 予測時間)。予測時間は 3.45 × (錐の数 / 22741)^1.2 秒です。110k 錐で約 70 秒、160k 錐で約 110 秒になります。
   - あわせて、根の近くで起きる DLL の失敗（raw_cone 1.5〜3.5e-7、solver_status 2/5、上界の求解の 15〜30%）を減らします。具体的には、許容値と再中心化の見直し、または 1 回の再試行です。そうしないと失敗のたびに HSD（300 秒以上）に切り替わり、S1 と S2 の差（約 2 倍）の時間がかかります。
2. **チェーンの中の HSD の時間を規模に合わせる**
   - 今は HSD の下限時間を ContinueAccuracy の中でしか使っておらず、チェーンでは使っていません。
   - チェーンでも、HSD の時間を 1.5 × (20 + 0.0037 × 錐の数) 秒（上限 3600 秒）にします。これは DLL が失敗したときの安全網です。
3. **チェーンを早く始める**：薄層を検出したら、標準の細分をせず、coarse_0 の直後にチェーンに入ります。P06A はこれで 1.91% でした。P06N で効果を出すには、5. の下界の改善と組み合わせる必要があります。
4. **パラメータの変更**
   - 下界：θ 0.9 → 0.7、ラウンドを 2〜4 から 4〜6 回に、上限を 4000 → 8000 にします（要素数あたりの改善は θ0.7 の方がよい結果でした）。
   - 上界：上限を 3500 → 5000、ラウンドを 10 → 14 にします。P06N は 0.6896 に 4946 要素が必要でした。
   - 全体の上限時間（`ADAPT_OPTIONAL_DEADLINE_SECONDS`、既定 0）を P06 用に決めます。
5. **下界の指標を、成熟した上界から作る**：下界のラウンドは、上界がある程度細かくなってから（例：上界 2000 要素以上）始めるか、最新の最良上界で毎回指標を作り直します。後半ラウンドで下界を始める検証は下の追記に書きます。
6. **下界が 1 回失敗しても止めない**：根が決まらなかったときは、その系列を 1 つ前に戻し、θ を小さくして（例：0.5）再挑戦します。下界の等式補正（試作の Es Es^T を直接分解する方法）の VBA への移植も、約 2500 要素を超える下界には必要になる見込みです。
7. **上界の細分の効率**：Fix8 の方向性細分は、試作の最良（0.68957 に 2575 要素）より約 2 倍の要素を使っています。試作の手順（12 ラウンド、θ0.8 の区間など）との差を調べる余地があります。

## 制約と注意

- Python（Clarabel）と VBA（DLL/HSD）で、収束・時間・合否が同じになる保証はありません。時間はすべて見積りで、測定値ではありません。
- 下界の HSD の時間（DLL の 4 倍）は較正していません。
- この結果は速度改善として確認したものではありません。

## 追記（2026-10-19 夕方）：試作との違いと、試作に合わせた結果

### Fix8 の移植と試作の違い

試作（`G1R20_P06_meshproto_20261018/proto/run_pipe.py`）と見比べると、Fix8 の移植には次の3つの違いがありました。

1. **中央線の入れ方**：試作では、中央線を粗いメッシュに先に入れ、そのメッシュで根を求めてから（329 要素）、指標による細分を始めます。Fix8 は、中央線を1段目の分割にまとめて入れています（中央線を入れたメッシュで解き直していません）。
2. **下界の指標**：試作では、下界のメッシュ上で上界を 1.08×Fs で1回解き、その速度場を指標に使います。Fix8 は、最良の上界メッシュの値を、要素の重心の位置で読み取って使っています。
3. **入替え前の速度**：試作では、上界の入替えの前に、細分したメッシュで上界を解き直します。Fix8 は、前のメッシュの速度を写して使っています。

`sim/vba_chain.py` に、それぞれを切り替える `--mid-separate`、`--lower-own-upper`、`--flip-fresh` を加えて確かめました。3つすべてを入れた `protomatch` は、試作の上界の経過（345 要素 0.7787、417 要素 0.7348、489 要素 0.7114、581 要素 0.7111）を同じ値で再現しました。
