# G1R20 Fix6候補 動作テスト（Winmax2、2026-10-18、日本時間）

未公開の候補です。workbook SHA256 `bd1eee7cad7534883aa8e14cd1530a5cd18cdc76d8ddfe8ff1fdb8b605f8289e`、DLLはFix4/Fix5と同一です。
Winmax2（Ryzen 7 7840U）、AC電源、2%標準プリセットで実行しました。P06N/P06Aは対象外です（別PCで実施予定）。

## 変更（RPX_Solve.basのみ）
1. HSDの時間上限は、現在の反復のOPTIMAL判定と証明書判定が済んでから確認します。Fix5では先に時間を確認していたため、収束済みの反復を判定前に捨てることがありました。
2. 時間上限に達しても、反復が終盤（主残差<1e-9、双対残差<1e-8、gap<1e-6(1+|obj|)）にあれば、上限の1.5倍まで継続できます。設定は `HSD_ENDGAME_GRACE=0.5` です。採用基準（OPTIMAL許容値と候補監査）は変えていません。

- P10Aは、790要素の上界の求解が終盤延長で収束しました（HSD 37反復、全体421秒）。上界は2.04794から2.04459に下がりました。
- accuracy_3（1185要素）の上界は、上限に達した時点で終盤に入っていなかったため打ち切られました（25反復、primal 4.9e-7）。精度は変わらず、約440秒が無駄になりました。
- own_q8の上界は再利用されず（`not_certified_same_mesh_q`）、790要素を約425秒かけて再計算しました。Fix5より遅い主な理由は、この再計算と、打ち切られたaccuracy_3の2つです。
- D05A、P02A、P05AではHSDの時間上限に一度も達していません。どれも変更部分の影響を受けず、Fsは一致しました。時間の差は同じ経路での変動です。
