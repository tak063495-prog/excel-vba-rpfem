## エラー名の問題と、符号の証拠不足を分ける

Issueは、D05AのFs=1でHSDがOPTIMAL・目的値2.40457・物理監査合格なのに、別の原dual復元がraw stat約1429.671、cone約4.3e-6、dual目的値約0で棄却され、`HSD_NOT_CONVERGED`になったと報告しています。完全な実行時の問題行列・HSD dual・復元candidateは今回の資料にありません。この値は報告値として扱います。

[RPX_Fs.bas L271以降](https://github.com/tak063495-prog/excel-vba-rpfem/blob/1ab383bbc1764249a4320ca28ed3ac6682c8fbac/versions/G1R20_Fix4/src/vba/RPX_Fs.bas#L271)は、上界の逆側符号が必要な場面で原dualを要求し、不合格ならこのエラーを発生させます。**エラー名がHSD自身の未収束と原dual回復棄却を区別していないことは確定**です。

一方、上界の最小化で目的値2.40457の許容速度場があるだけでは、真の最小値が1より大きいとは証明できません。目的値が1を超える側のFs符号には、原dual等の監査済み証拠が必要です。HSDのOPTIMALという文字列だけで復元失敗を無視して続ける提案は、根の保証を弱める可能性があります。

## 相対閾値に変えるだけでは報告候補を救えない

新実験のD05A原costの∞ノルムは1906.2283737862776で、元P02Aの1000倍です。この別メッシュの値を、Issueの1429.671と同一だとは扱いません。

ゼロdualを元問題で検査すると、stationarityは1906.228…、コストで正規化しても残差は1、原dual目的値は0です。仮に報告値1429.671が原costノルムだったとしても、相対閾値`1e-7*1429.671 ≈ 1.43e-4`に対して残差1429は約1000万倍大きく、目的値も1.000003以上という条件を満たしません。

従って、絶対1e-7の微小な丸め誤差だけが原因、相対化だけで直る、とはいえません。スケールが求解の難しさを増している可能性はPython比較で支持されますが、今回のnative candidateの原因が座標復元、ray・打切り点、数値的失敗のどれかは、実ベクトルとsolver statusが必要です。

## 変数単位・目的関数・等式行を別々に戻す

新実験の正の変数単位変換とcone行スケーリングは、元の係数と門を変える処理ではありません。`x=k*u`、正の行スケールR、正の目的係数aに対して、変換後の問題は

```
A' = R*A
rhs' = R*rhs/k
cost' = a*k*cost
x_original = k*u
dual_original = R*dual_transformed/(a*k)
```

です。SOCごとに同一の正倍率を使ってconeを保存し、最後に未縮約・未正規化の原問題で再監査します。目的関数だけを正規化した経路でdualの戻し忘れを与える負の比較も記録し、原門で棄却しています。

VBAのHSDは、原costをXQScaleで割り、等式行を行ノルムで割って解きます。commit済みHSD dualを原候補にするなら、別のスケールs_Qと行ノルムr_iについて

```
y_original[i] = s_Q*y_HSD[i]/r_i
z_original    = s_Q*z_HSD
```

が必要です。ただし、現在のnative原dual helperは最初から原cost・原行を解く別問題なので、このHSD用の逆変換を無条件に重ねてはいけません。根拠原文23箇所と11ファイルのSHAは `reports/ISSUE28_SOURCE_ANCHORS.json`、詳しい静的考察は `reports/ISSUE28_CODE_FINDINGS.md` に保存しました。

長さ1000倍の面積総和では浮動小数点の丸めが拡大するため、新実験のメッシュ検査は正の三角形と正規面積へのroundoff boundを確認します。座標・材料・荷重・原演算子・物理監査の閾値は変えていません。

## 再監査コード自身のCPU差も確認した

初回のWindows CIでは、同じ入力・ソースのSHAが一致しても、再構築した原行列のバイトSHAが一致せず停止しました。CIで原配列を保存し、ローカルでOpenBLASのCPU別演算経路を切り替えると同じ差を再現しました。これは今回追加したPython再監査の移植性の問題であり、報告されたVBAの原dual回復失敗を説明する証拠にはしません。

実CI配列の最大差は、P02AのG／costで2.22e-16、D05AのGで2.22e-16・costで2.274e-13でした。疎構造は完全一致です。元配列は`reports/ci_assembly/`、全6ベクトルの元門の再計算と比較結果は`reports/portability/CI_PORTABILITY_ANALYSIS.json`にあります。

保存時の原行列SHAと完全一致する参照配列を保全し、参照NPZ・元ソース・入力のSHAを先に検査します。再構築行列との形・型・CSCのindex/pointer・cone構成は完全一致を要求し、有限の浮動小数配列だけに`32*eps*max(1, max(abs(参照配列)))`の係数丸め幅を使います。バイトSHAが異なることは結果に明記します。

その後も原問題でのstationarity1e-7・cone1e-8・目的値1.000003の門を維持し、保存例の合格・棄却を別々に再計算します。係数同一性の比較幅と、物理・dualの合格条件は別です。旧manifestと旧verifier原本は保持し、新adapter・参照行列のhash記録を別に追加しました。通常・Sandybridge・Nehalemの実行経路を切り替える検証と、許容係数差を超える変更を拒否する負例も収録しています。

新規runの記録SHAは、参照原行列か現在の再構築行列のいずれかと厳密一致する必要があります。そのどちらとも一致しない第三のSHAには行列証拠がないため、明示的に拒否します。6条件の不足・重複、ヘッダやメタデータの不一致、構造・型・非有限値・参照NPZ改変等を含む16条件の検査もPASSしました。
